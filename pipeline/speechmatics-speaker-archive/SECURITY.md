# Безопасная эксплуатация

Это локальная административная панель. Встроенных учётных записей, CSRF-защиты
и разграничения прав в ней нет. Не публикуйте её порт напрямую в интернет.

## Секреты

1. Скопируйте `.env.example` в `.env`.
2. Создайте отдельный `APP_SECRET_KEY` командой
   `python -c "import secrets; print(secrets.token_urlsafe(48))"`.
3. Вставьте ключи провайдеров только в локальный `.env` или в локальную страницу
   настроек. `.env` исключён из Git.
4. Никогда не публикуйте `data/app.db`: в ней могут находиться зашифрованные
   настройки, а их защита зависит от `APP_SECRET_KEY`.
5. Если ключ когда-либо попал в чат, лог, commit или screenshot, отзовите его у
   провайдера и создайте новый.

`docker compose` требует явно заданный `APP_SECRET_KEY` и по умолчанию привязывает
панель только к `127.0.0.1`. Для удалённой работы используйте VPN либо reverse
proxy с TLS и аутентификацией.

## Данные и медиа

- Исходный каталог WAV монтируется в контейнер как read-only (`/audio:ro`).
- Репозиторий не содержит WAV, референсы голосов, БД, raw-транскрипты, клипы,
  подготовленные FLAC, журналы заданий или ответы провайдеров.
- В публичный Issue не прикладывайте локальные пути и сырые ответы API без
  предварительного удаления чувствительных данных.

Перед публикацией выполните:

```bash
python scripts/check_public_tree.py
git status --short
```

Проверка является страховкой, а не заменой ручного просмотра staged diff.
